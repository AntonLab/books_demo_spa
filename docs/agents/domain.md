# Domain Docs

Single-context repo: read `CONTEXT.md` (the glossary) and the ADRs in `docs/adr/` that touch the area you work in, and use the glossary's terms. Skip a `superseded` ADR unless you need its history; a new ADR carries the same frontmatter (`status`, `date`, `supersedes` / `superseded-by` / `amends` / `amended-by`) and the ADR it changes gets the reverse link. Surface a contradiction with an ADR explicitly rather than overriding it silently. `/domain-modeling` updates both files.
